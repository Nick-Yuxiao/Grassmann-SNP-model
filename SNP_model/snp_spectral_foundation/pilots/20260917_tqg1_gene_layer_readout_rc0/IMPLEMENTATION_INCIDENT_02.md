# 事故 02：协变量与基因型共用同一个 ridge 惩罚

_发现：2026-09-17,在为 TQ-B1 做合成数据 smoke 时｜影响：**改变 rc0 `B−A` 的解释**_

## 现象

TQ-B1 的合成 cohort 里,真实信号明确存在,但 `B`(协变量 + cis dosage)在**几乎每个基因上**都输给 `A`(仅协变量),且 `A` 的 R² 对所有基因恒等:

```
G1_000 alpha=1000  r2A=+0.0523  r2B=+0.0490  delta=-0.0033
G1_001 alpha=1000  r2A=+0.0523  r2B=+0.0244  delta=-0.0278
G1_005 alpha=1000  r2A=+0.0523  r2B=+0.0341  delta=-0.0181
mean delta over 8 genes: -0.01127
```

改为"协变量不受惩罚"之后,同一份数据同一个种子:

```
gate TRAIT_A: B-A delta=+0.004984  CI=[5.2e-05, 0.011385]  PASS
```

符号翻转。

## 原因

rc0 的 `fit_ridge` 对设计矩阵**整体**标准化后施加同一个 `alpha`,协变量列与基因型列受同等惩罚。

于是:

- `A` 只有 15 个协变量列,验证集会选到很小的 alpha,协变量系数几乎不被压缩;
- `B` 有 15 + 256 列,其中绝大多数不携带信号,验证集被迫选到很大的 alpha 来压制它们;
- 这个大 alpha **同时压扁了协变量系数**,而协变量恰恰是 `A` 里唯一有效的预测源。

结果是 `B` 为了压住噪音基因型,牺牲掉了 `A` 已经拿到的协变量预测力。**`B` 因此结构性地劣于 `A`,与有无遗传信号无关。**

正确做法是对协变量块施加零惩罚。这样 `alpha → ∞` 时基因型系数归零、协变量系数回到 OLS,`B` 精确退化为 `A`,`B` 不可能结构性输给 `A`。

## 对 rc0 结论的影响

rc0 的四个臂全部受影响,受影响程度按新增特征数递增:

| Arm | 新增特征 | 受惩罚的协变量 |
| --- | --- | --- |
| A | 0 | 是,但 alpha 很小 |
| C_gene | 160 | 是,alpha 被抬高 |
| B | 256 | 是,alpha 被抬高 |
| C_full | 4096 | 是,alpha 被抬得最高 |

因此:

- **`B − A = −0.0144` 不能再被读作"加性 dosage 没有信号"。** 其中有多少来自协变量被过度压缩、多少来自信号缺失,rc0 的产物无法拆分。
- `TASK-INELIGIBLE` 这个判定**依然成立**,因为它的含义是"本轮不可解释",而现在不可解释的理由增加了一条。
- **`C_gene − B = −0.0315` 的方向仍可能是真的**（`C_gene` 只有 160 个新增特征,受惩罚程度低于 `B` 的 256,若纯粹是惩罚效应,`C_gene` 反而应当占优）,但其**数值不可信**。
- `C_gene − C_full = −0.0232` 与惩罚效应的方向一致（`C_full` 多 4096 列,受害最深）,因此这条次要结论**基本应当作废**。

## 处置

rc0 已冻结,**不修改其代码、配置或产物**,`FREEZE.sha256` 保持原值。`results/REPORT.zh-CN.md` 追加指向本文件的说明,不改动其数字。

修复已进入 `../../protocols/20260917_tqb1_gene_effect_bar_rc0/`:
`PrimalRidge` 接受 `penalty_mask`,协变量块取 0。两条回归测试锁住该行为——
一条要求 `alpha → ∞` 时精确退化为协变量模型,另一条在纯噪音基因型上要求
unpenalised 版本严格优于 shared-penalty 版本。

任何 TQ-G1 rc1 必须带上同一修复,否则 `B` 这个基线没有意义。

## 教训

**基线必须被给予公平的机会。** 如果一个"更强的臂"在结构上无法退化成"更弱的臂",那么两者之差就不是在比较信息量,而是在比较惩罚结构。

判据很简单:**加入全零信息的特征,不应使任何臂变差。** rc0 的估计量不满足这一条,而这在合成数据上一测就能发现——这个检查本应在冻结之前就做。
