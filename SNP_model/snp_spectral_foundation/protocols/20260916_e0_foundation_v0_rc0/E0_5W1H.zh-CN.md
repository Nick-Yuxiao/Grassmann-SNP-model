# E0 genotype-only local encoder：5W1H 执行版

_一句话：从随机初始化开始，只用 genotype，在 family-disjoint 与 locus-disjoint 的共同基准上检验共享 local encoder 是否学到可迁移的 genotype distribution。_

---

## ❓ Why：为什么做

已发表研究与既有结果支持 genotype 中存在稳定可学习的 AF、population/PC、local LD 与 haplotype structure，但“结构存在”不等于“我们的 encoder 能在新家系和未见区段迁移”，更不等于 phenotype relevance。

E0 的正面目标是证明：在排除亲缘个体泄漏与相邻区段 LD 泄漏后，从头训练的 local encoder 对 masked genotype 的概率预测，以预注册的实际幅度胜过 AF/经验频率、局部统计模型和 haplotype-HMM。它不要求模型删除 MAF、LD、haplotype 或 ancestry；这些是 foundation modelling 的合法信号。

## 🧪 What：做什么

- 输入：双等位 SNP 的 ALT dosage token `0/1/2`、missing/mask token、train-only ALT AF、整数 bp 坐标导出的相对位置与 marker gap。
- 任务：20% callable SNP masked prediction；primary metric 为三分类 cross-entropy。
- 模型：E1 primary local Transformer；最多再评估 E2 ancestry-conditioned 和 E3 capacity-sensitivity。
- 基线：M0a 经验 genotype 概率、M0b AF/HWE、M1a 局部正则 multinomial、M1b Beagle haplotype-HMM。
- Co-primary：`δ_S` 衡量新家系/已见区段，`δ_X` 衡量新家系/未见区段。
- E0 不使用 phenotype，不检验 biological specificity、causality 或 Grassmann 优势。

## 👥 Who：哪些个体

- 以 pedigree/kinship connected component 为不可拆分单位，而不是按 individual 随机切分。
- 默认候选亲缘边为冻结 kinship `≥0.0442`；最终来源、版本和阈值在 UKB inventory 后绑定。
- Components 按 `70/15/15` 分为 train/validation/test，并在 ancestry、sex、array 与 batch strata 内平衡。
- AF、PC、imputation、standardization、LD blocks 和所有拟合参数只使用 train families。
- 所有 encoder、baseline、C/D/E 和后续 phenotype probe 共用同一 family manifest。

## 🧬 Where：哪些 genomic regions

- 统一 build、contig、REF/ALT 与 normalized variant identity。
- 在 train families 或冻结外部 reference 上构造 LD blocks。
- 按 chromosome、genomic position、block size、MAF 和 LD density 分层抽取多个连续 validation/test held-out runs，而不是散点留出单块。
- 只在 held-out run 外边界设置 guard；宽度取 encoder receptive field、相邻 LD block 与 `1 cM` 的最大值。
- 再用 train families 检查跨边界 common-variant `r² ≥ 0.1`；不通过则扩展 guard 或合并 atomic block。
- MHC、inversion 与 long-range-LD 区域作为 atomic super-block 或从 primary claim 排除后单报。

## 📅 When：按什么顺序

1. `R1`：UKB 只读 inventory 与授权、build、phasing、sample、variant、kinship、map 绑定。
2. `R2`：冻结 sample/family/variant/block/mask manifests；独立 validator 必须 PASS。
3. `R3`：只在 validation 上冻结 B*、三个 recipe 之一、checkpoint、micro-batch 与 runtime。
4. `R4`：test 只打开一次，同时计算 E0-S 与 E0-X。
5. `R5`：发布 Foundation-v0 或限定范围的负结果；保存 checkpoint、manifests、logs 与 hashes。

Phenotype `H vs raw dosage` 是独立平行路线：只能在 encoder 冻结后、使用另一个预注册 test firewall 评估，不能反向选择 E0 recipe。

## ⚙️ How：怎么训练和判定

E1 使用 256-SNP windows、4 层 pre-norm Transformer、`d_model=128`、8 heads、FFN 512。模型跨窗口共享参数，禁止 global block ID、variant lookup 和 block-specific parameters；输入浮点 genomic coordinates 会显式失败。

每个 recipe 最多 3 个 training seeds，最多 100,000 updates，early stopping 只看 validation family × block macro CE。test 前用 one-standard-error rule 选择更小的合格模型。三 recipe 均失败即结束本轮，不能继续追加架构救援。

评价先在 family-component × LD-block cell 内平均 masked sites，再对 families 与 blocks 等权宏平均；用 5,000 次 two-way clustered bootstrap 得到 paired 95% CI。PASS 同时要求：

\[
\delta_S \ge 1\%,\qquad \delta_X \ge 1\%,
\]

并且两者 95% CI 下界均大于 0。只显著但低于 1% 记为 `STATISTICALLY_POSITIVE_PRACTICALLY_TIED`。

| 结果 | 允许的结论 |
| --- | --- |
| 仅胜 M0，不胜 M1/HMM | 学到 context，但没有 neural headroom |
| `δ_S` PASS、`δ_X` FAIL | same-panel/local imputation encoder，不称跨区段 foundation encoder |
| `δ_S`、`δ_X` 均 PASS | 冻结 Foundation-v0；phenotype 价值另行检验 |
| 三个 recipes 均 FAIL | 结束当前架构/目标预算；不否定其他 genotype foundation 路线 |

Grassmann 不参与 primary gate；其既有 `NO_GO` 不停止 local/raw/PCA 或其他 foundation architecture。
